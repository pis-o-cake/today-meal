# 3일 해커톤 실행 계획

현재 목업과 구현 사이의 차이를 R-ID로 추적한다. 기능 완료는 검증 증거가 있을 때만 판정한다.

## 기준 시점과 일정

9/29 문서 정비 시점의 [현재 목업](../../mockup/README.md)과 코드 정적 확인을 기준으로 한다.
앱·목업·이력 서버 코드가 동시에 수정 중이므로 이 표는 최종 실기기 판정이 아니다.
이전 측정값과 당시 장애 기록은 [9/28 보존 기록](hackathon-3day-2026-09-28-record.md)에 있다.

| 일정 | 목표 |
|---|---|
| 9/28 | 초기 골격·음성·재고 실험. 당시 기록 보존 |
| 9/29 | 문서/목업 기준 통일, 부분 등록·후속 질문·기록·추천의 사용자 흐름 연결 |
| 9/30 ~18:00 | 필수 시나리오·실기기·설치/배포 검증 후 제출 |
| 10/1 | 남은 결함·녹화·발표 자료. 필수 완료 후에만 추가 기능 |
| 10/2 | 검증된 기능만 시연 |

일정은 목표이며 미완료 기능을 완료로 바꾸는 근거가 아니다. iOS·부분 등록 등이 남으면 범위와
제출 상태를 명시적으로 갱신한다. 기술 품질이나 구현 난도로 기준을 조용히 낮추지 않는다.

### 이번 문서 정비의 판정

목업 기준·제품 정책·UI 상태·개발 절차·검증 기준을 연결했다. 과거 기술 선택과 관찰은 보존하고
현행 요구에서 분리했다. 이는 R-01~08의 런타임 구현을 완료했다는 뜻이 아니다.
자동 검사와 재현성 조치의 실행 결과는 작업 종료 전에 이 절에 기록한다.

### 9/29 화면 구현의 판정

목업 개정판의 16개 화면과 테마 4종을 Flutter 로 옮겼다. 이번에 더한 것은 조리 탭·조리
진행·조리 완료·재료 상세 넷과 서버의 영상 레시피 도메인이다. 자동 검증은 `flutter analyze`
0건, `flutter test` 113건, `pytest` 185건, `ruff` 통과, `scripts/check-repository.py`
통과다.

실기기(SM-E426S, Android 13)에서 확인한 것: 오늘·냉장고·조리·기록·마이페이지 다섯 탭,
추천으로 조리 시작 → 5단계 진행 → 완료(서버가 되물어 차감하지 않았고 화면이 그 물음을
그대로 보여줬다), 재료 상세에서 수량을 고쳐 저장 → 서버 기록에 `adjust 계란 8 → 9 ·
화면에서 고쳤어요` 로 남고 목록이 갱신됨, 파스텔·다크 전환.

**아직 완료가 아니다.** 아래는 이번 작업에서 닫지 못한 것이다.

| 남은 것 | 어디 |
|---|---|
| 확인 질문의 선택지 버튼 — 서버가 선택지를 주지 않는다 | R-01 |
| HTTPS. 세션 토큰이 평문 구간을 지난다 | R-12 |

| iOS 빌드·실행. 이번 검증은 Android 한 대뿐이다 | R-10 |
| 카카오 콘솔 키·키해시 등록과 실기기 로그인 검증 | R-12 |
| Google·Apple 로그인. Apple 은 유료 개발자 계정이 필요하다 | R-12 |

## 장애 요인과 조치

| 요인 | 영향 | 필요한 조치 |
|---|---|---|
| 단일 발화 API에 후속 대화 식별이 없음 | 질문에 답해도 원래 초안을 완성하지 못할 수 있음 | R-01에서 DB·API·앱 계약과 통합 검증 |
| 동일 저장소에서 앱·목업 수정 진행 | 문서·테스트 기준이 작업 중 바뀔 수 있음 | 최신 diff·목업 해시를 확인하고 관련 검증 재실행 |
| Canvas 런타임·blob은 저장소 외부 | 새 checkout만으로 동일 렌더링을 보장하지 못함 | R-08에서 export 증거 확보. 단독 index를 정본으로 대체하지 않음 |
| OS별 음성 지원·배포 미확인 | Android 성공을 iOS 성공으로 확장할 수 없음 | OS별 V-01·12 실행 |
| HTTPS 미확인 | 세션 토큰이 평문으로 지나갈 수 있음 | 공개 배포 전 전송 구간 암호화 확인. 그 전에는 같은 망 안에서만 시연 |
| 기본 가구가 게스트 공용 | 둘러보기 사용자끼리 같은 냉장고를 봄 | 게스트 경로를 유지하는 대가. 시연 데이터만 둔다 |
| 테스트 DB 없음 | 일부 통합 검증 skip 가능 | 로컬 PostgreSQL 준비 후 실행, skip을 통과로 세지 않음 |

막힌 작업은 해당 R-ID의 기대 동작·현재 결과·다음 조치로 인계한다. 외부 이슈를 만들더라도
이 표와 연결하고 기능의 완료 상태는 증거가 생긴 뒤에만 변경한다.
