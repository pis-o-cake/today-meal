# 검증하는 세션으로 바꾼다

## 맥락

이전 결정은 **인증을 하지 않는 것**이었다. `X-User-Id`·`X-Household-Id` 헤더를 검증 없이
믿고, 헤더가 없으면 기본 가구를 썼다. 근거는 "MVP 는 주방에 고정한 태블릿 한 대에서 쓰므로
로그인이 관문이 아니다" 였고, 그 전제에서는 맞는 판단이었다.

두 가지가 바뀌었다.

1. 목업 `mobile-2026-09-29-r2` 가 로그인·가입·마이페이지를 화면 범위에 넣었다(UI-09~11).
2. 계정을 만들면 **계정마다 다른 가구**를 갖는다. 그 순간 헤더 하나로 남의 냉장고를 읽고
   쓸 수 있게 된다 — 태블릿 한 대라는 전제가 사라졌기 때문이다.

"인증하지 않는다" 와 "계정이 있다" 는 함께 갈 수 없다.

## 결정

이메일·비밀번호 로그인과 **폐기 가능한 서버 세션**을 둔다.

- 비밀번호는 bcrypt 해시로만 저장한다. 원문은 어디에도 남기지 않는다.
- 세션 토큰은 256비트 난수이며 DB 에는 SHA-256 해시만 둔다. DB 가 새도 그 값으로
  로그인할 수 없다.
- 호출자는 `Authorization: Bearer` 로 판정한다. `X-User-Id`·`X-Household-Id` 는
  **더 이상 읽지 않는다.**
- 토큰이 없으면 게스트이며 기본 가구를 쓴다 — 로그인 없이 둘러보는 경로를 유지한다.
- 토큰이 있는데 유효하지 않으면 401 이다. 조용히 게스트로 떨어뜨리지 않는다. 그렇게 두면
  사용자는 자기 냉장고를 보고 있다고 믿으면서 남의 데이터를 본다.
- 가입하면 그 사용자의 가구를 새로 만든다. 기본 가구에 묶으면 가입한 사람들이 같은
  냉장고를 함께 본다.

## 대안

| 대안 | 채택하지 않은 이유 |
|---|---|
| 헤더 신뢰 유지 | 계정마다 가구가 다른 순간부터 남의 데이터에 접근할 수 있다 |
| JWT | 로그아웃해도 만료까지 유효하다. 되돌리려면 어차피 서버 상태가 필요하다 |
| 제공자(카카오·Google) 먼저 | 키와 검증 경로가 없다. 검증 없이 성공 처리하면 인증이 아니다 |
| 기기 로컬 계정 | 서버가 가구를 가르지 못한다. 기기를 바꾸면 자기 데이터를 잃는다 |

## 결과

**얻는 것**

- 계정이 자기 가구만 본다. 헤더 위조로 남의 냉장고를 열 수 없다.
- 로그아웃이 세션을 실제로 끝낸다.
- 비밀번호·토큰 원문이 저장소에 없다.

**치르는 것**

- 가입하면 **빈 냉장고로 시작한다.** 게스트로 둘러보던 재고는 기본 가구의 것이며 옮겨오지
  않는다. 가구 간 이관 정책은 정하지 않았다.
- 기본 가구는 여전히 누구나 읽고 쓴다. 게스트 경로를 유지하는 대가다.
- 토큰은 HTTPS 가 아니면 그대로 노출된다. **공개 배포 전에 전송 구간 암호화를 확인한다.**
- 소셜 로그인은 여전히 501 이다. 화면에 버튼은 두되 성공으로 처리하지 않는다.
- 비밀번호 재설정 경로가 없다. 잊으면 되돌릴 방법이 없다.

남은 것은 작업표의 R-12 에서 추적한다.
