# 모바일 화면과 사용자 흐름

현재 목업의 화면·행동·저장·복귀를 연결한다. 정상 화면뿐 아니라 오류와 미완료 상태에도 같은 계약을 적용한다.

## 적용 범위

[현재 목업](../../mockup/README.md)의 계정 화면을 포함한 12개 화면을 Flutter로 구현하는 계약이다.
시각과 배치는 화면 HTML을 따르고, 아래 동작·실패·복구 규칙은 목업에서 생략된 상태를 보완한다.
이 문서는 구현 요구다. 현재 충족 여부는 [작업표](../plan/hackathon-3day.md)가 갖는다.

핸드폰 세로가 기준이다. 뭐 먹지?·냉장고·기록·마이페이지 네 탭의 선택, 검색, 스크롤을 대화 전후에 유지한다.
메뉴 상세는 선택한 탭 위에 쌓고 뒤로 가면 같은 위치로 돌아온다. 대화는 어느 화면에서든
최상위 오버레이로 연다. 조리 중에도 음성 상태와 취소 경로가 가려지지 않아야 한다.

## 컴포넌트와 표현 규칙

### 공통 디자인

- Pretendard 가변 폰트, 반투명 유리 카드와 하단 탭을 사용한다.
- 화면 테마는 파스텔·화이트·글래스·다크 4종이며 마이페이지에서 고른다(UI-11).
  파스텔이 기본이고 등급 색이 배경까지 물든다. 화이트는 배경을 평면으로 두고 카드만
  세우며, 글래스는 흐림과 안쪽 광택을 더하고, 다크는 배경을 고정한다.
  **색은 `app/lib/core/design/skin.dart` 한 곳에만 적는다.** 화면이 색을 직접 적으면
  테마를 하나 더 넣을 때 빠뜨리는 화면이 생긴다. 고른 테마는 기기에 저장한다.
- 냉장고 친구 `Mascot2`를 듣기·확인·반영에 공통 사용한다. 듣기는 보라·파동·실제 입력 크기,
  확인은 주황, 반영은 초록이다. 어두운 재료 그래프는 이전 시안이다.
- 단계 표시의 현재 막대는 길고 두껍게, 지난 단계는 체크, 다음 단계는 회색으로 표시한다.
  현재 이름은 듣는 중·확인 중·반영 완료이며 빛 흐름과 맥박 점을 함께 쓴다.
- 하단은 뭐 먹지?·냉장고·기록·마이페이지 4개 탭. 첫 탭 아이콘은 A 수저다.
- 스플래시·로그인·권한 배경은 #F6F7FF→#E1E6FF, 캐릭터는 #C7CFFF 계열이다.
- 날짜는 화면에서 YYYY.MM.DD, 음성에서 YYYY년 M월 D일로 연도를 포함한다.
  출처가 불분명한 연도를 단지 표시 형식을 맞추려고 생성하지 않는다.
- 색·간격·타이포는 `app/lib/core/design/`의 토큰에 모은다. 화면마다 새 팔레트를 만들지 않는다.
- 상태는 색·문구·아이콘을 함께 제공한다. 터치 영역은 최소 44 logical px이며 스크린리더 이름을 둔다.
- 기한 종류·확인 여부·수량 확실성을 서로 구분한다. 미확인 값을 0이나 안전 등급으로 바꾸지 않는다.
- 마이크 진입은 호출어 또는 상단 호출 상태 칩이다. 별도 떠 있는 마이크 버튼을 추가하지 않는다.
  음성 불가 시 같은 진입 영역에서 텍스트 입력·권한 복구로 연결하는 보조 상태를 제공한다.
- 재료명·긴 발화·큰 글자에서 세로 스크롤을 허용한다. 하단 탭·시스템 제스처가 본문을 가리지 않는다.
- 태블릿 폭에서는 같은 정보·동작을 넓혀 배치한다. 폰 검증 전에 태블릿 전용 경험을 확장하지 않는다.

### 계정 진입과 설정

로그인·가입은 실제 서버 검증을 전제로 한 목표다. 목업의 `href=Permission`은 화면 이동 예시이며
모든 로그인 버튼이 인증 없이 성공하는 구현 계약이 아니다. 첫 실행은 스플래시→로그인으로,
로그인·가입·둘러보기 이후 필요한 권한 안내→홈으로 연결한다. 로그인 없이 둘러보기를 유지한다.
게스트 데이터와 계정 데이터의 병합·이관 정책은 R-12의 설계 항목이며 임의 합치지 않는다.

이메일 형식·필수 입력·비밀번호 확인 불일치는 입력 옆에 표시한다. 회원가입의 비밀번호는 목업의
영문·숫자·8자 이상 조건을 표시하고 서버도 검사한다. 약관은 필수 2개(서비스 이용약관,
개인정보 수집·이용), 선택 1개(기한 알림)이며 모두 기본 해제다. 모두 동의·개별 동의를 연동하고
필수 동의와 입력 조건이 충족돼야 가입 버튼을 활성화한다. 약관 링크는 실제 내용을 열어야 한다.
목업의 가입 버튼은 동의만 검사하므로 입력 검증은 구현 보완 항목이다.

로그인은 비밀번호 보기/숨기기, 비밀번호 찾기, 회원가입을 제공한다. 카카오·Google은 양 OS,
Apple은 iOS에 표시한다. 반경 12px 버튼과 중앙 정렬을 유지하고 점선 로고는 공식 자산으로
교체한다. 버튼의 계정 선택 취소·제공자 실패·네트워크 오류를 로그인 성공으로 처리하지 않는다.
비밀번호 찾기·약관 본문은 별도 목업이 없으므로 R-12에서 경로와 상태를 설계하며 자기 페이지
새로고침으로 대체하지 않는다. 제공자 연동 전에는 운영 로그인 정보를 수집하지 않는다.

마이페이지는 실제 닉네임·로그인 제공자를 표시한다. 예시 “철님”, “카카오 계정”을 하드코딩하지
않는다. 게스트는 게스트 표시와 로그인 진입을 제공한다. 음성 응답 토글은 TTS만 제어하고
마이크 음소거와 구분한다. 기본 인분·늘 있는 양념·피하는 재료는 추천에 반영한다.
호출어 행은 현재 선택된 Hey Kitchen과 지원 범위를 설명하며 임의 커스텀 학습 화면을 만들지 않는다.

기한 알림·알림 시점은 앱 내 기한 표시 설정이다. OS 푸시를 구현했다고 표현하지 않는다.
신규 사용자의 선택 동의는 기본 꺼짐이며 목업의 토글 켜짐은 기존 사용자의 예시 상태다.
기존 사용자는 저장된 설정을 표시한다. 로그아웃은 세션을 종료하고 계정 화면 데이터를 지운 뒤
로그인으로 이동한다. 게스트 지속성·서버 세션 정책은 R-12/13에서 API와 함께 확정한다.

### 홈 밴드와 재료 타일

밴드 순서는 `기한 지났어요 → 얼마 안 남았어요 → 며칠 남았어요 → 넉넉해요 → 날짜 몰라요`다.
내부 키 expired·urgent·soon·fresh·unknown은 유지한다. 최초 선택은 재료가 있는
urgent, soon, expired, fresh, unknown 순으로 찾는다. 이후에는 사용자 선택을 유지한다.
모든 재고가 비어 있으면 빈 냉장고와 첫 등록 안내를 보여준다. 없는 메뉴 카드를 채우지 않는다.

밴드·기한 경과·사용 가능 여부는 서버가 판정한다. 앱은 색과 문구로 표현한다.
목업의 막대는 **상태를 요약하는 장식**이며 식품 안전도·남은 수명 퍼센트가 아니다.
검증된 비율을 서버가 제공하기 전에는 밴드별 고정 길이로만 표시하고 숫자·퍼센트를 노출하지 않는다.
미확인은 점선, 기한 경과는 경고 문구를 함께 표시한다. 날짜가 없는 항목에 기한을 생성하지 않는다.

### 부분 등록과 확인 질문

“두부 두 모랑 계란 열 개 넣었어. 두부는 10월 3일까지야”는 계란을 먼저 반영하고 두부의
날짜 종류를 질문한다. UI-04 상단에는 서버가 저장을 확인한 계란만 표시한다.
후속 “소비기한이야”는 두부 초안의 종류를 채우며 계란을 다시 등록하지 않는다.

하나의 사용자 요청을 대화 그룹으로 묶고 각 적용·미완료 항목을 서버가 구분해야 한다.
8초 안에 답변을 시작하면 해당 발화가 끝날 때까지 기다린다. 시간 초과·닫기에서는 미완료
두부 초안만 폐기하고 이미 저장한 계란은 유지한다. “계란은 등록했고 두부는 아직이에요”처럼 알린다.
UI-04의 되돌리기는 현재 그룹에서 이미 적용된 변경을 되돌리고 남은 초안도 닫는다.
전체 완료 후 UI-05의 되돌리기는 그룹에 속한 계란·두부를 함께 되돌린다.

선택지 터치와 음성 답변은 같은 서버 명령 경로를 사용한다. 원래 요청·후속 답변·재시도 식별은
[아키텍처의 목표 계약](../architecture/README.md)에 따른다. 이 경로가 없는데 UI만 성공으로
전환해서는 안 된다. 네트워크 오류로 처리 여부를 모르면 재조회하고 이미 반영된 항목을 유지한다.

| 처리 중 | 확인하고 있어요·중복 입력 방지 | 실패 시 재시도. 요청 ID를 유지해 중복 반영 방지 |
| 확인 질문 | 질문·선택지·적용/미완료 항목 | 낭독 후 8초 후속 입력. 답변 중 타이머로 자르지 않음 |
| 반영 결과 | 서버가 확인한 변경과 되돌리기 | 최소 4초 표시하고 TTS 완료 후 복귀. 오류·거절은 반영했어요로 표시하지 않음 |
| 배경/음소거 | 감지하지 않는 사실 표시 | 전경 복귀 시 권한 재확인. 사용자가 음소거했으면 자동 해제하지 않음 |

마이크 소유권은 `VoiceSessionManager`가 관리하고, 화면의 결과 보존은 대화 ViewModel이 관리한다.
TTS가 끝났다는 이유만으로 결과가 즉시 사라지지 않는다. 화면을 닫는 것과 DB 변경 취소를 구분한다.
조리 모드는 전경에서만 화면을 유지하며 종료·뒤로·배경 전환 시 유지 요청을 해제한다.

### 목업에 없는 예외 상태

| 상황 | 보완 동작 |
|---|---|
| 재고 0개 / 검색 0건 | 각각 첫 등록 안내 / 검색·필터 해제. 같은 빈 화면으로 처리하지 않음 |
| 로딩 | 현재 화면 구조를 유지하고 진행 표시. 목업의 예시 데이터를 대입하지 않음 |
| 통신 실패 | 읽기 실패와 저장 여부 미확정을 구분. 저장 요청은 같은 ID로 상태 확인·재시도 |
| 추천 불가 | 부족·확인 필요를 설명. 없는 재료를 보유로 꾸미지 않음 |
| 되돌리기 실패 | 기존 결과를 유지하고 오류·재시도 표시. 성공 토스트 금지 |
| 대화 중 뒤로 | 제출 전 취소 / 제출 후 결과 확인. 사용자에게 저장 여부를 정확히 안내 |
| 긴 목록·접근성 글자 확대 | 스크롤 허용, 수량·기한·주 행동이 잘리지 않음 |

## 검사 기준

[검증 기준](../verification/mvp.md)의 V-01~V-14를 따른다. 화면별 목업과 같은 데이터·뷰포트로
비교하고 권한 거부·빈 상태·네트워크 실패도 확인한다. 스크린샷은 색·배치 검증이며 DB 무결성의
증거가 아니다. DB 테스트 통과도 UI 연결 완료의 증거가 아니다.

시각 수정은 화면 ID·변경 이유·목업 변경·앱 변경·전후 증거를 함께 남긴다. 이미 선택된 캐릭터나
내비게이션을 기능 구현 편의로 바꾸지 않는다. 동작을 바꾸면 제품 정책과 이 문서를 함께 갱신한다.
