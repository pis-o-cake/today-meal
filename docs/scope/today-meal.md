# 오늘 뭐 먹지? — 3일 해커톤 제공 범위

**핸드폰에 말을 걸어** 식재료를 등록·사용·정정하고, 남은 재료로 오늘의 메뉴를 정하는 앱을
3일 안에 완성한다. Flutter 하이브리드로 만들어 Android 와 iOS 에 같은 코드를 쓴다. 이 문서는 무엇을 만들고 어디까지 하면 완료인지를 정하며,
제품 동작의 상세 정책은 [기획서](../product/proposal.md)가 갖는다. 개발 순서와 일정은
[3일 실행 계획](../plan/hackathon-3day.md)이, 구조는
[아키텍처](../architecture/README.md)가 갖는다.

일정 기준은 **개발 9/28~9/30, 제출 9/30 18:00, 시연 10/2**다. 발표 자료는 제출 이후에 준비한다.

### 기기 방향 — 핸드폰이 먼저, 태블릿은 다음

초기 구상은 주방에 고정한 태블릿의 상시 대기였다. **MVP 는 핸드폰으로 간다.** 이유는 셋이다.

- **검증 대상이 늘어난다.** 태블릿을 새로 두는 부담 없이 지금 쓰는 기기로 바로 써볼 수 있다.
- **장보기 중에 쓸 수 있다.** 마트에서 부족한 재료를 확인하는 것은 핸드폰만 할 수 있고,
  이 흐름이 쿠팡 연계와 자연히 이어진다.
- **어디서나 조회한다.** 냉장고 앞이 아니어도 무엇이 있는지 확인한다.

**주방 고정 태블릿의 상시 대기는 후속 방향으로 유지한다.** Flutter 를 고른 이유가 여기 있다 —
같은 코드로 폰과 태블릿을 함께 내고 레이아웃만 갈린다. 그래서 화면은 **핸드폰 세로를 기준으로
만들되 태블릿 가로로 확장 가능하게** 설계한다.

이 전환이 바꾸는 것은 **웨이크워드의 범위**다. 핸드폰에서 상시 대기는 성립하지 않으므로
F-01 은 **앱이 화면에 떠 있는 동안만** 감지한다. 백그라운드 상시 대기는 후속이며,
발표에서 상시 대기를 구현했다고 말하지 않는다.

## 전체 범위

기능은 셋으로 가른다. **필수**는 9/30 제출물에 반드시 든다. **추가**는 필수가 끝난 뒤 남는
시간에만 손을 댄다. **후속**은 이번 범위 밖이며 발표에서 구현했다고 말하지 않는다.

### 필수 — 제출물의 조건

| ID | 기능 | 한 줄 정의 |
|---|---|---|
| F-01 | 전경 웨이크워드 | 앱이 화면에 떠 있는 동안 호출어에 반응하고 응답 후 대기로 돌아온다 |
| F-02 | 음성 명령 전사 | 호출 후 한국어 명령을 텍스트로 바꾼다 |
| F-03 | 음성 응답 | 처리 결과를 한국어로 읽고 마이크 소유권을 감지기에 넘긴다 |
| F-04 | 자연어 복합 등록 | 한 문장의 여러 재료를 각각의 묶음으로 등록한다 |
| F-05 | 기한·개봉·보관 기록 | 날짜 종류와 출처를 보존해 저장한다 |
| F-06 | 재고 조회 | 음성과 냉장고 화면으로 현재 재고를 확인한다 |
| F-07 | 사용량 차감 | "계란 두 개 썼어"를 사용 이벤트로 반영한다 |
| F-08 | 현재 잔량 보정 | "계란 네 개 남았어"를 절대값 보정으로 반영한다 |
| F-09 | 정정 | 직전 명령을 교체하고 중복 차감하지 않는다 |
| F-10 | 취소 | 직전 변경 묶음을 되돌린다 |
| F-11 | 변경 이력 | 입고·사용·보정·정정·취소를 시간순으로 보여준다 |
| F-12 | 먼저 쓸 재료 | 기한 임박·개봉·잔량 미확인 재료를 대시보드에 띄운다 |
| F-13 | 메뉴 추천 | 현재 재고로 가능한 메뉴를 최대 3개 제시한다 |
| F-14 | 메뉴 상세 | 인분에 맞는 재료·부족 재료·조리 순서를 보여준다 |
| F-15 | 홈 화면 | 메뉴·먼저 쓸 재료·호출 상태를 앱을 열면 바로 보여준다 |
| F-16 | 배포 | 설치 가능한 APK·iOS 빌드와 접속 가능한 서버를 낸다 |

### 추가 — 필수 완료 후에만 착수

| ID | 기능 | 착수 조건 |
|---|---|---|
| F-17 | 유튜브 영상 검색 | F-13이 끝나고 3일 차 오전에 여유가 있을 때 |
| F-18 | 영상 레시피 분석 | F-17이 실제 영상 ID를 반환할 때 |
| F-19 | 영상 재료 ↔ 재고 대조 | F-18이 재료·분량을 구조화해 낼 때 |
| F-20 | 쿠팡 검색 연결 | F-19가 부족 재료를 확정할 때 |
| F-21 | 라벨 사진 날짜 인식 | 위 넷과 무관하게 독립 착수 가능 |
| F-22 | 간편 로그인 | 위 다섯과 무관하게 독립 착수 가능 |

### 후속 — 이번 범위 밖

**주방 고정 태블릿의 상시 대기**(백그라운드 웨이크워드 · 상시 켜진 대시보드 · 부팅 자동 실행),
영수증·주문내역 대량 등록, 가족 공유와 모바일 푸시, 남은 음식 관리, 스마트 기기 연동·QR
용기·AR, 쿠팡 파트너스 상품 카드와 주문·배송 연동. 시연과 발표에서 구현한 것으로 소개하지
않는다.

태블릿 상시 대기는 **제품 방향으로 유지하되 이번 범위가 아니다.** 같은 Flutter 코드에
태블릿 레이아웃과 포그라운드 서비스를 더하면 되는 구조로 만들어 둔다.

### 간편 로그인의 범위 — 보안은 전부 제외

F-22는 **사용자를 식별하는 것까지만** 한다. 보안은 의도적으로 전부 배제했다. 아래를 구현하지
않으며 **발표와 시연에서 인증·보안을 구현했다고 말하지 않는다.**

| 하지 않는 것 | 대신 |
|---|---|
| 제공자 토큰의 서명·만료 검증 | 클라이언트가 보낸 제공자 사용자 ID를 그대로 신뢰 |
| 세션·refresh 토큰·만료 | 세션을 두지 않음 |
| 비밀번호와 해시 | 비밀번호 로그인 자체를 두지 않음 |
| 권한 검사·역할 분리 | 사용자 하나가 가구 하나에 속하는 것만 확인 |
| 요청 위조·재생 공격 방어 | 하지 않음 |

이 범위로 충분한 이유는 셋이다. 3일 안에 인증을 제대로 만들면 필수 기능이 줄고, MVP는 주방에
고정한 태블릿 한 대에서 쓰고, 지금 확인할 가설은 "말로 재고를 관리하는가"이지 "안전하게
로그인하는가"가 아니다.

다만 **이 상태로 공개 배포하지 않는다.** 실제 사용자를 받기 전에 인증을 다시 설계한다.

### 범위 밖이라고 명시할 것

앱은 식품의 안전 여부를 판정하지 않는다. 바코드만으로 소비기한을 자동 완성하지 않는다.
말하지 않은 사용 내역을 추론해 차감하지 않는다. 냉동 전환이나 소분을 이유로 기한을 연장하지
않는다.

## 기능별 완료 기준

각 항목은 실제 태블릿에서 확인해야 완료다. 빌드 성공이나 단위 테스트 통과는 완료가 아니다.

### 음성 계층

| ID | 완료 기준 |
|---|---|
| F-01 | 앱이 화면에 떠 있는 상태에서 버튼 조작 없이 연속 5회 호출·응답·대기 복귀. 감지기와 전사기가 마이크를 동시에 점유하지 않음. 앱이 배경으로 가면 감지를 멈추고 그 사실을 표시 |
| F-02 | 수량·날짜가 든 명령 10개를 전사해 품목·숫자·단위가 텍스트에 남음. 한국어 인식 가능 여부를 실기기에서 확인 |
| F-03 | 응답 재생 중 자기 음성이 명령으로 재처리되지 않고, 재생 완료·오류 양쪽에서 감지기가 재기동 |

### 재고 계층

| ID | 완료 기준 |
|---|---|
| F-04 | "두부 두 모랑 계란 열 개 넣었어. 두부는 소비기한 10월 3일. 둘 다 냉장실" 한 문장이 두 묶음으로 저장되고 두부만 기한을 가짐 |
| F-05 | 소비기한·유통기한·품질유지기한·제조일을 서로 다른 값으로 저장. 종류를 모르면 미확인으로 남고 임의 변환 0건 |
| F-06 | 음성 조회와 냉장고 화면이 같은 잔량을 보여줌. 잔량 미확인 항목은 숫자를 지어내지 않고 미확인으로 표시 |
| F-07 | 계란 10개 → "두 개 썼어" → 8개. 잔량보다 큰 사용은 음수를 저장하지 않고 현재 잔량을 확인 |
| F-08 | "네 개 남았어"가 차감이 아니라 절대값 보정으로 기록되고 이력에서 구분됨 |
| F-09 | "두 개가 아니라 세 개"가 직전 사용을 3개로 교체해 잔량 7개. 3개 추가 차감 0건 |
| F-10 | "방금 거 취소"가 직전 변경 묶음 전체를 되돌리고 이전 잔량을 복원 |
| F-11 | 위 다섯 동작이 시간순으로 남고, 각 항목이 명시값인지 추정값인지 구분됨 |

**핵심 통합 시나리오** — 이 한 줄이 통과해야 필수 재고 기능이 완료다.

`계란 10개 등록 → 2개 사용(8) → 사용량을 3개로 정정(7) → 정정 취소(8) → 현재 4개 남음으로 보정(4)`

각 단계의 잔량과 변경 이력을 함께 확인한다.

### 추천·화면 계층

| ID | 완료 기준 |
|---|---|
| F-12 | 기한 임박·개봉·잔량 미확인 재료가 대시보드에 뜨고, 재고를 바꾸면 갱신됨. 기한 경과 항목은 오늘 요리 후보에서 빠짐 |
| F-13 | 평가용 재고 10종에서 필수 재료가 없는 메뉴를 '지금 가능'으로 표시하는 사례 0건. 추천 이유와 먼저 쓰는 재료가 함께 보임 |
| F-14 | 인분을 바꾸면 재료 수량이 따라 바뀌고, 부족 재료와 확인 필요 재료가 구분됨. 메뉴 조회만으로 재고 변경 0건 |
| F-15 | 핸드폰 세로에서 홈 화면이 메뉴·먼저 쓸 재료를 보여주고, 조리 모드에서 화면을 유지하며 15분 간격 호출에 응답. 화면 조작 없이 정상 흐름이 완료됨 |
| F-16 | 다른 기기에서 APK를 내려받아 설치하고, 서버 주소만으로 재고 등록·조회가 동작. iOS 는 실기기 설치까지 확인 |

### 추가 기능

| ID | 완료 기준 |
|---|---|
| F-17 | 검색 API의 실제 영상 ID로 링크를 만들고, 모델이 URL을 지어낸 사례 0건. 실패 시 가짜 카드 0건 |

### 전 기능 공통 불변 조건

아래는 기능이 아니라 어느 기능에서도 깨지면 안 되는 조건이다. 서버 코드가 지키며 기능
완료 판정에 포함한다.

- 모델 출력은 실행 제안이다. 서버가 동작·단위·대상·날짜·잔량을 검증한 뒤 실행한다.
- 같은 발화에 붙은 명령 ID는 재시도해도 한 번만 반영된다.
- 음수 잔량을 저장하지 않는다.
- 미확인 기한을 확정값으로 승격하지 않는다.
- 조회·검색·영상 시청은 재고를 바꾸지 않는다.
- 사용자에게 보이는 문구는 리소스 파일에서 온다. 로그와 내부 예외는 영어로 고정한다.
