# 오늘 뭐 먹지? — 제공 범위와 완료 기준

핸드폰에서 말로 재고를 관리하고 메뉴를 정하는 경험을 제공한다. Android·iOS를 대상으로
Flutter 코드를 공유한다. 제출 목표는 9/30 18:00, 시연은 10/2다. 일정 때문에 완료 기준을
충족하지 못하면 미완료로 남기고 범위를 바꿀 때 이 문서를 먼저 갱신한다.

[제품 정책](../product/proposal.md)은 저장·질문·취소 의미를, [UI 계약](../ui/mobile.md)은
[현재 목업](../../mockup/README.md)의 화면 동작을 정한다. 구현 상태는 [작업표](../plan/hackathon-3day.md)가 갖는다.

## 기능별 완료 기준

단위 테스트·빌드·사용자 시나리오·실기기 확인을 구분한다. 기능 완료는 해당 시나리오를
실제 대상 기기에서 확인하고 증거를 남긴 상태다. OS별로 따로 판정한다.

| ID | 완료 기준 |
|---|---|
| F-01 | 표시 호출어와 실제 감지가 일치. 전경에서 버튼 없이 5회 호출·응답·복귀. 배경·음소거에서 중단. 마이크 동시 점유 없음. 대기 중 **LLM 요청 0회**, STT 외부 처리 가능성 안내 |
| F-02 | 수량·단위·날짜가 든 한국어 명령 10개에서 해당 정보가 전사에 남음. 무음·권한 해제 시 저장 없음 |
| F-03 | 한국어 낭독 중 자기 응답 재처리 없음. 완료·오류 양쪽에서 복구. 결과 화면 최소 4초·낭독 완료까지 유지 |
| F-04 | 두부·계란 명확한 복합 발화가 두 묶음으로 저장. 불명확한 두부만 보류하고 계란을 먼저 저장. 후속 답변은 두부만 적용. 재시도 중복 0건 |
| F-05 | 기한 종류·출처·원문 보존. 모르면 미확인. 개봉·이동은 수량을 바꾸지 않음. 근거 없는 날짜 생성·연장 0건 |
| F-06 | 음성과 화면의 동일 잔량. 2열 타일·검색·보관 필터. 미확인 수량을 숫자로 대체하지 않음 |
| F-07 | 10개에서 2개 사용 후 8개. 초과 사용은 저장 없이 확인 |
| F-08 | 네 개 남았어 → 절대값 4. 사용과 다른 보정 기록 |
| F-09 | 2개 사용을 3개로 교체하면 잔량 7. 추가 3개 차감 없음 |
| F-10 | 직전 변경 그룹 전체 역산. 부분 등록 중 취소는 적용분 역산·초안 폐기. 재시도로 추가 역산 없음 |
| F-11 | 발화·응답·변경 전후·명시/추정 표시. 정정은 한 행동으로 묶음. 최신 되돌릴 수 있는 변경에만 버튼 |
| F-12 | 기한 임박·개봉·잔량 미확인 표시. 재고 변경 후 갱신. 소비기한 경과는 요리 후보 제외 |
| F-13 | 평가용 10종 재고에서 없는 필수 재료를 지금 가능으로 표시 0건. 음성 요청도 추천 화면으로 연결. 이유·먼저 쓸 재료 표시 |
| F-14 | 인분 변경 시 서버 환산 수량 표시. 부족·확인 필요 구분. 상세 조회만으로 재고 변경 없음 |
| F-15 | 현재 목업 12화면과 정상·빈·실패 상태 연결. 조리 모드 중 화면 유지·15분 간격 호출. 조리 시작·종료만으로 차감 없음 |
| F-16 | 깨끗한 checkout에서 문서대로 의존성·설정·DB 준비·검증. 다른 Android에 APK 설치·서버 등록/조회. iOS는 별도 빌드·실기기 설치 증거 |

핵심 재고 시나리오는 `10개 등록 → 2개 사용(8) → 3개로 정정(7) → 정정 취소(8) → 4개로 보정(4)`다.
수량과 이력을 함께 확인한다. 부분 반영의 시간 초과는 이미 저장된 항목까지 취소하는 동작이 아니다.

|---|---|

| F-18 | 확인한 공개 영상의 재료·분량·출처 추출. 없는 수량 생성 0건 |

| F-20 | 한글 검색어 외부 검색·복귀. 클릭만으로 재고 변경 0건 |
| F-21 | 읽지 못한 날짜 생성 0건. 사용자 확인 후 저장 |
| F-22 | 이메일·비밀번호와 카카오, 폐기 가능한 세션. 계정마다 가구를 분리. 제공자 토큰은 서버가 제공자에게 직접 물어 확인. Google·Apple 은 연동 전이라 성공으로 처리하지 않음 |

### 공통 불변 조건

모델은 제안만 하고 서버가 검증·실행한다. 요청 재시도는 한 번만 적용한다. 음수 수량과 근거
없는 단위 변환을 저장하지 않는다. 미확인 날짜·수량을 확정하지 않는다. 조회·추천·조리 시작·
외부 검색은 재고를 바꾸지 않는다. 사용자 문구는 앱·서버의 문자열 리소스로 관리한다.
목업 데이터로 API 실패를 숨기지 않는다. 검증 조건과 증빙 형식은 [검증 기준](../verification/mvp.md)을 따른다.
