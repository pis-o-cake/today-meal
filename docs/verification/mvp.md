# MVP 사용자 흐름 검증

필수 기능의 통과 기준과 실행 조건을 정한다. 시험 결과와 실기기 증거는 별도로 기록한다.

## 검증 범위

[필수 F-01~F-16](../scope/today-meal.md)과 [현재 목업](../../mockup/README.md)의 동작·화면·
저장소 재현성을 판정한다. 이 문서는 시험 규격이며 통과 결과가 아니다.
추가 기능은 착수 시 제품 정책을 기준으로 검증 항목을 확장한다.

## 시험 조건

- 앱·서버 커밋 또는 작업 트리 diff, 목업 판본·파일 해시, 실제/가짜 LLM 여부를 기록한다.
- OS·기기 모델·화면 크기·글자 배율·한국어 STT/TTS 지원·권한·네트워크·시간대를 기록한다.
- 음성은 호출→준비 응답→명령 순서로 시험한다. 거리·소음·성공/시도 횟수를 남긴다.
- 표준 재고는 별도 테스트 가구/DB에서 준비한다. 실제 사용자 재고를 초기화하지 않는다.
- 비교 기준일은 2026-10-02, 두부 소비기한 10/03, 삼겹살 소비기한 09/30, 미확인 계란 등
  목업 예시를 사용하되 기준일과 데이터가 시연용임을 표시한다.
- DB 없이 skip된 테스트는 통과 수에 포함하지 않는다. 화면 캡처와 API 테스트는 별도 증거다.

## 실행과 증빙

자동 검증 진입점은 `sh scripts/verify.sh`다. 저장소 검사는 Python 표준 라이브러리로 수행한다.
모델 실제 평가에는 별도 키·예산이 필요하므로 자동 검증에 무조건 호출을 추가하지 않는다.

작업표의 해당 R-ID에 다음 형식의 증거를 연결한다. 원자료가 없는 이전 통과 기록은 이전 기록으로
표시하며 현재 버전의 통과로 옮기지 않는다.

```text
일시 / 실행자 / 앱·서버 커밋 또는 diff / 목업 판본·해시
V-ID / F-ID / UI-ID
기기·OS·화면·글자배율·권한·네트워크·거리·소음 / 실제·가짜 LLM
초기 재고·기준일 / 실행 단계 / 기대값 / 실제값
통과·실패·미실행·skip / 로그·이미지·영상 경로 / 잔여 문제 R-ID
```

검증 결과 문서가 필요하면 `verification-result` 유형을 별도 경로로 배정해 작성한다.
아직 실행하지 않은 항목은 미실행으로 남긴다. 인수 전 시연 대상은 실기기 검증된 기능만 선정한다.
