# 0001. MVP 기술 설계

현행 기술 선택의 배경과 폐기된 선택을 구분하고, 목업 계약을 구현할 때 지켜야 할 경계를 정한다.

## 제안 요약

핸드폰용 Flutter 앱과 FastAPI·PostgreSQL 서버를 분리한다. 모델은 서버의 Gemini 연결부로
호출하고 음성 입출력은 기기 내장 서비스를 사용한다. 현재 구현 구조는 [아키텍처](../architecture/README.md),
사용자 경험은 [현재 목업](../../mockup/README.md)과 [UI 계약](../ui/mobile.md)이 정한다.
이 설계는 실기기 인수 전 `draft`다. 구현된 코드가 있다는 이유로 모든 선택을 검증 완료로 올리지 않는다.

| 결정 | 이유 | 비용·한계 |
|---|---|---|
| 앱·서버 분리 | 키와 재고 계산을 서버에 두고 검증 규칙을 한 곳에서 변경 | 네트워크·배포 대상 둘 |
| Flutter | Android·iOS 코드 공유, 폰 우선과 태블릿 후속 방향 | 마이크·인식·TTS는 OS별 실기기 검증 필요 |
| 클라우드 LLM·Gemini | 이틀 개발에서 기능을 빨리 연결. 유튜브 영상 속 조리 과정을 단계별 조리 안내로 연결 | 제공자 종속·영상 길이 비례 비용. 모델명은 설정이며 접근·품질은 실측 필요 |
| 내장 음성 인식 반복 청취 | 이전 호출어 수단 실패 후 채택된 현행 구현 | 외부 음성 처리·배터리·발열·청취 구간 공백 |
| 호출어 “헤이 키친”·넓은 판정 | 영어 호출어를 고려하던 조건에서 한국인이 영어식으로 발음해도 크게 벗어나지 않는 문구. 판정을 넓혀 시연의 호출 누락을 줄임 | 오호출 가능성 증가 |
| 전경 한정 감지 | 핸드폰에서 앱을 열고 조리하는 범위로 제한 | 잠금·백그라운드는 감지하지 않음 |
| PostgreSQL 16 | UUID·JSONB·배열·NUMERIC·트랜잭션 활용 | 로컬에도 PostgreSQL 필요 |
| 검증하는 세션 | 계정마다 가구가 달라 헤더 신뢰로는 남의 냉장고가 열린다([ADR-0001](../adr/0001-verified-sessions.md)) | 가입하면 빈 냉장고로 시작. HTTPS·비밀번호 재설정 미확인 |

## 설계

### 앱·서버·데이터 경계

재고 수량·단위 환산·날짜·기한·중복 방지는 서버만 갖는다. 앱 단독 DB와 모델 직접 호출은
키 노출과 검증 코드 중복 때문에 채택하지 않았다. 앱은 Repository로 서버를 읽고 UI 상태를
관리한다. ViewModel은 마이크를 직접 다루지 않고 `VoiceSessionManager`를 사용한다.

PostgreSQL의 UUID는 요청 멱등 키, JSONB는 모델 제안·레시피 단계, 배열은 재료 별칭,
NUMERIC은 소수 수량을 표현한다. SQLite로 별도 개발 스키마를 유지하지 않는다.
현재값과 변경 원장을 함께 저장하며 정정·취소는 역산 이벤트로 기록한다.
상세는 [DB 설계](0002-database.md)를 따른다.

### 클라우드 LLM과 Gemini 선택 배경

작업표의 일정은 3일(9/28~9/30 제출)로 세웠지만, 개발자 설명에 따르면 실제 개발에 쓴 시간은
이틀이다. 모델 선택은 이 기간 안에 기능을 연결하는 것을 기준으로 했다. 관련 기능은
F-18 영상 분석과 F-25 조리 안내다.

| 단계 | 내용 |
|---|---|
| 당시 제약 | 실제 개발 시간이 이틀이라 빠르게 개발하고 기능을 연결해야 한다 |
| 선택 이유 | 그래서 클라우드 LLM을 쓴다. 그중 Gemini를 고른 핵심 이유는 유튜브 링크로 영상 속 조리 과정을 분석하고 그 결과를 단계별 조리 안내(F-18 → F-25)로 잇는 기능이다 |
| 실제 관찰 | 한국 요리 채널은 설명글에 재료·계량만 적고 조리 순서는 영상 안에만 두는 경우가 많아, 설명글만 읽던 이전 방식으로는 대부분 순서를 얻지 못했다([아키텍처](../architecture/README.md#영상-레시피)). 3편 실측 비용은 [작업표](../plan/hackathon-3day.md) R-11에 있다 |
| 보완 방식 | 영상 주소를 Gemini에 직접 입력해 순서를 읽고, 제목·설명글·자막은 별도 경로로 받아 계량을 보강한다 |
| 감수한 한계 | 제공자 종속, 영상 길이에 비례하는 비용과 길이 상한, 네트워크·키 필요, 영상 분석 품질의 실기기·실영상 검증 필요 |

명령 해석·메뉴 추천·영상 분석이 한 제공자의 `LlmGateway`로 모인 것은 이 선택에 따른 구현상의
이점이며 주된 선정 이유가 아니다.

“유튜브 API”는 두 경로를 구분해 쓴다. 영상 내용 분석은 Gemini에 영상 주소를 넘기는 경로이고,
제목·설명글 등의 조회는 YouTube Data API 경로다. YouTube Data API는 영상 내용을 분석하지 않는다.
두 경로의 입력 규칙은 [아키텍처](../architecture/README.md#영상-레시피)가 정한다.

### 음성 수단의 변경 이력

| 순서 | 당시 선택과 관찰 | 현재 취급 |
|---|---|---|
| 1 | Porcupine. 개인 이용 제한 때문에 쓸 수 없다고 판단해 제외 | 폐기. AccessKey 설치 지침 제거. 후속 목표로도 두지 않음 |
| 2 | sherpa-onnx 한국어 스트리밍 ASR int8 약 132~134MB. 갤럭시 SM-E426S에서 감지 경로 실행 중 프로세스 종료 기록 | 폐기. 모델 다운로드·번들 절차 제거 |
| 3 | 기기 인식 서비스 반복 청취·전사 판정. 한때 인식률 때문에 기본 문구를 “자비스”로 둠 | 현행 구현. 기본 문구 “헤이 키친”, 이전 호출어는 별칭. 실기기 품질은 R-02 |

모델 로드 성공과 감지 중 종료 기록은 시험 경로가 다른 과거 관찰이며 안정성 통과로 합치지 않는다.
구체적 관찰·프롬프트 평가 조건은 [9/28 기록](../plan/hackathon-3day-2026-09-28-record.md)에 보존한다.

### 호출어 선정 배경

F-01 호출어 감지의 수단과 문구를 정한 당시 판단이다. 표의 앞 두 행은 문구를 정할 때의 판단이고,
뒤 세 행은 이후 구현에서 관찰하고 보완한 내용이다.

| 단계 | 내용 |
|---|---|
| 당시 제약 | 한국어 호출어가 필요하고 일정이 짧다. 개발자는 한국어 지원과 인식 성능을 보고 Porcupine을 먼저 검토했으나 2026년 6월의 개인 이용 제한 때문에 쓸 수 없다고 판단했다. 성능 평가는 당시 개발자의 판단이다 |
| 선택 이유 | 짧은 일정에서 쓸 수 있는 오픈 모델을 대안으로 검토·선택했다. 당시 대안은 한국어 호출어를 지원하지 않아 영어 호출어를 고려했고, 한국인이 영어식으로 발음해도 원래 발음에서 크게 벗어나지 않는 표현으로 “Hey Kitchen / 헤이 키친”을 정했다 |
| 실제 관찰 | 문구 선정만으로는 인식이 충분하지 않았다. 첫 낱말이 짧고 약하게 발음돼 매번 다른 글자로 받아써졌다 |
| 보완 방식 | 호출어 모델을 다시 학습하지 않고, 비슷하게 인식되는 단어와 발음 변형을 분석해 여러 전사 결과를 같은 호출로 받아들이도록 판정 규칙을 넓혔다. 현재 규칙은 [아키텍처](../architecture/README.md#음성-구현)에 있다 |
| 감수한 한계 | 시연에서 불렀는데 반응하지 않는 문제를 줄이는 것을 우선했다. 허용 범위를 넓힌 만큼 TV·대화 소리 등으로 잘못 깨어날 가능성이 커진다 |

영어 호출어를 고른 것은 문구를 정할 당시 검토한 대안의 제약 때문이다. 저장소 기록에 남은 이후
구현은 위 표의 sherpa-onnx 한국어 ASR을 거쳐 기기 내장 인식(`ko_KR`)으로 바뀌었다. 문구 선정 때
검토한 오픈 모델의 이름과 이 이력 사이의 순서는 기록에 남아 있지 않다. 현행 기기 인식은 한국어로
전사하므로 “헤이 키친”을 한글과 로마자 전사 양쪽으로 판정한다.

Porcupine의 개인 이용 제한은 9/28 기록에 “2026-06-30 무료 티어 종료, 가입은 업무용 이메일만,
유료 월 $899부터”로 남아 있다. 이 가운데 무료 티어 AccessKey를 2026-06-30 이후 비활성화한다는
Picovoice 안내는 [사용자 공유 글](https://community.home-assistant.io/t/fyi-picovoice-confirmed-free-tier-accesskeys-will-stop-working-after-june-30-2026/1012744)로
확인했다. 업무용 이메일 가입 제한과 가격은 외부 근거를 찾지 못해 당시 기록으로만 둔다.
어느 것도 현재 요금·이용 조건으로 제시하지 않는다.

검토했던 openWakeWord·microWakeWord 직접 학습은 데이터·학습·기기 최적화 시간이 필요해
선택하지 않았다. davoice 커스텀 모델 요청, Vosk도 당시 일정·연결부 조건 때문에 채택하지 않았다.
이들을 현재 지원·가격 비교로 해석하지 않는다. 버튼만으로 음성을 시작하는 흐름은 핵심 손 없는
사용 경험을 충족하지 못하므로 호출어가 필수이고 터치는 보조다.

현재 플러그인은 `speech_to_text`·`flutter_tts`이며 기기별 한국어 지원이 다를 수 있다.
감지와 전사는 공유 SpeechEngine을 순차 사용하고 TTS 중에는 전사하지 않는다.
현행 코드의 마이크 해제 대기와 재시작 간격은 코드가 정한다. 기기에서 실패하면 조건을 기록한다.

**대기 중 LLM 요청 0회**를 요구한다. 이전 “대기 중 STT·클라우드 요청 0회” 조건은 현행 수단과
맞지 않아 제공 범위에서 변경했다. 온디바이스 모델이 없는 기기에서는 외부 인식이 가능하므로
완전 오프라인·로컬 전용 대기라고 소개하지 않는다.

제품과 코드의 기본 호출어는 “헤이 키친”이다. “자비스”·“헤이 냉장고”는 이전 호출어 별칭으로만
받는다. 호출 성공·누락·오호출의 실기기 확인은 R-02다.
기술 구현의 문구를 근거로 목업과 제품 문구를 일방적으로 바꾸지 않는다.

### UI와 API 설계의 순서

사용자 흐름·상태·화면에서 필요한 데이터를 먼저 정한 뒤 서버 계약과 앱을 연결한다.
서버 응답 형태에 맞춰 목업을 축소하거나, 목업의 예시를 고정 데이터로 넣어 연결된 척하지 않는다.
부분 등록·후속 질문·그룹 취소는 [아키텍처 목표 계약](../architecture/README.md)의 R-01을 따른다.
현재 DB·API의 단일 명령 구조가 이를 이미 지원한다고 가정하지 않는다.

조리는 진행 화면이 단계·타이머·낭독·화면 유지·음성 명령을 맡고, **추천 조리의 완료가 재고를 뺀다.**
차감 기준은 화면에서 조리한 인분이며 되돌리기는 그 명령의 실제 취소 요청이다. 메뉴 상세에
레시피 일괄 차감 버튼을 두지 않는다 — 차감은 조리를 마쳤다는 사실에 붙는다.
질문 8초·결과 최소 4초의 화면 수명은 오디오 상태와 분리한다.

### 모델과 인증

AI는 한국어 발화의 의도와 영상의 재료·조리 순서를 구조화하고, 서버는 그 제안의 대상·수량·
단위·날짜를 검증해 실행한다. 자연어 해석의 유연함을 얻으면서 재고 계산과 저장의 일관성을
유지하려는 경계다. 모델에 저장 판단과 SQL 실행을 맡기지 않는다.

사용자가 모든 값을 다시 입력하지 않도록 확인이 필요한 정보만 묻고, 모르는 수량은 미확인으로
남긴다. 요청 ID는 재시도의 중복 반영을 막고 변경 원장은 정정·취소로 복구하는 근거가 된다.
복합 등록에서 명확한 항목을 먼저 반영하고 나머지만 질문하는 것은 제품 목표이며, 현재의
전체 보류 방식과 차이는 R-01에서 추적한다.

영상 분석 결과는 F-18에서 F-25의 조리 단계로 이어진다. 조리 중 필요한 순서와 시간을 앱에서
확인하고 낭독·음성 명령을 사용할 수 있게 하는 흐름이다. 영상 분석의 정확성과 단계 조작의
동작은 각각 V-14와 V-08로 확인한다. 영상 조리는 완료해도 자동 차감하지 않으며, 추천 메뉴의
완료 차감과 되돌리기는 V-15로 별도 검증한다.

`LlmGateway`를 교체 지점으로 유지하고 실제 제공자는 하나만 운영한다. 명령 해석·추천·영상
분석의 입력·예산·평가는 구분한다. 키가 없으면 Fake가 선택되므로 가짜 응답 테스트와 실제
Gemini 평가를 따로 기록한다. 계정에 접근 가능한 모델명은 `.env`로 설정한다.

로그인은 필수 진입 조건이 아니다. 토큰이 없으면 게스트로 기본 가구를 쓰며 재고 조회와
명령이 모두 동작한다. 로그인은 **자기 가구를 갖기 위한 것**이다.

호출자는 `Authorization: Bearer` 의 세션으로 판정한다. 비밀번호는 bcrypt 해시로, 세션
토큰은 SHA-256 해시로만 저장하며 원문을 남기지 않는다. `X-User-Id`·`X-Household-Id`
헤더는 더 이상 읽지 않는다 — 계정마다 가구가 다른 뒤로는 그 헤더로 남의 냉장고를 열 수
있었다. 결정과 남은 위험은 [ADR-0001](../adr/0001-verified-sessions.md)에 있다.

CAUTION: 아직 남은 것 — HTTPS 확인, 비밀번호 재설정, 카카오 실기기 검증·Google/Apple 연동. 기본 가구는
게스트 공용이라 누구나 읽고 쓴다.

### 동결 조건

음성 왕복·수량 무결성·목업 사용자 흐름·OS별 설치를 [검증 기준](../verification/mvp.md)으로
확인하고, API·DB 목표 계약의 구현 차이를 해소한 뒤 `implemented`로 동결한다.
그 전에는 이 설계를 갱신하고, 동결된 결정을 뒤집을 때 ADR을 추가한다.
