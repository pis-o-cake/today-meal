# 발표 스토리와 개발 증거

발표는 10/2, 자료 제작은 9/30 18:00 제출 이후다. 7분 발표와 3분 질의응답을 목표로 한다.
현재 내용은 발표 구성안이며 구현 증거가 아니다. 기능 구현 지시는
[기능 개발 절차](../runbook/feature-development.md), 화면 기준은 [목업 인계](../../mockup/README.md)에 있다.

## 발표 구성

핵심 문장은 “장본 것을 말로 넣고, 쓴 것을 말로 빼고, 남은 것으로 오늘 저녁을 정합니다”다.
핸드폰을 주 기기로 보여주고 전경에서만 호출을 받는 범위를 설명한다.
유튜브 레시피 링크를 재료·조리 단계로 정리해 조리 안내로 잇는 경험도 소개한다. 이는 Gemini를
선택한 핵심 배경이며, 기술 선정 이유는 [기술 설계](../design/0001-mvp-technical-design.md)에 있다.
제출 버전의 확인 범위는 [제출 전 상태](../verification/results/2026-09-30-submission-status.md)를 따른다.

| 시간 | 내용 | 필요한 증거 |
|---|---|---|
| 0:00~0:40 | 재료는 있지만 메뉴가 떠오르지 않고 조리 중 입력이 번거로움 | 사용자 상황 예시. 조사 수치를 만들지 않음 |
| 0:40~1:15 | 폰에 말로 등록·사용·메뉴 요청 | 실제 앱 화면·표시 호출어 |
| 1:15~3:35 | 등록→사용→정정→메뉴 선택→조리 진행→완료 차감 | 같은 버전의 실기기 영상 또는 라이브 |
| 3:35~4:20 | AI 해석과 서버의 수량 검증 분리 | 현행 아키텍처 그림 |
| 4:20~5:35 | 요구·목업·UI 계약·구현·검증 연결 | 실제 문서·변경·화면 전후 |
| 5:35~6:20 | 확인한 결과와 남은 한계 | V-ID별 조건·기대값·실제값 |
| 6:20~7:00 | 실제 가정 사용·반복 기록·메뉴 실행 검증 계획 | 가설과 후속 범위 |

영상 URL 분석과 조리 연결은 구현이 있으며 V-14·V-08의 실기기 확인 뒤 시연에 포함한다.
영상 검색·쿠팡 검색은 미구현이므로 URL 입력과 검색 기능을 혼동하지 않는다.
태블릿 상시 대기·오프라인 호출 감지·공개 배포의 인증 검증은 완료했다고 말하지 않는다.

## 시연 시나리오

시연용 재고를 별도 준비하고 기준일·목업 판본·앱/서버 커밋을 맞춘다.

1. “헤이 키친”로 호출하고 준비 응답 뒤 두부·계란 등록을 말한다.
2. 명확한 등록과 질문이 필요한 등록을 구분한다. 부분 반영은 V-03 통과 때만 보여준다.
3. 계란 `10 → 8 → 7 → 8 → 4` 흐름과 대화형 기록을 확인한다.
4. 재고에 맞는 메뉴와 부족·확인 필요 재료를 보여준다.
5. 조리를 시작해 단계를 넘기고 완료한다. 완료가 조리한 인분만큼 차감하고 되돌릴 수 있음을
   보여준다. **V-15를 통과했을 때만 차감 장면을 시연한다.** 시작만으로 차감한다고 소개하지 않는다.

140초 시연이 길어지면 장면을 줄이고 예비 녹화본을 사용한다. 라이브·사전 녹화·설명 애니메이션을
구분한다. 목업 HTML을 실제 DB·음성 동작처럼 시연하지 않는다.

영상 경로를 확인했으면 메뉴 선택 장면 일부를 다음 흐름으로 대체한다. 확인한 공개 유튜브 URL을
입력하고 분석된 재료·단계를 보여준 뒤 조리 화면에서 단계 이동·낭독을 시연한다. 분석 대기 구간은
실제 녹화본으로 설명할 수 있다. 영상 조리는 완료해도 재고를 자동 차감하지 않는다고 안내한다.
실기기 확인 전에는 구현 흐름 설명으로만 다루며 동작 완료 장면을 대신 만들지 않는다.

## 제품 안에서 AI와 서버가 맡는 일

“AI는 말과 영상을 해석하고, 서버는 수량과 대상을 확인해 저장합니다. 잘못 반영한 내용은
변경 이력으로 되돌립니다.”를 기준 문장으로 쓴다.

예를 들어 “계란 두 개 썼어”에서 AI는 사용 의도·재료·수량을 제안한다. 서버는 어떤 재고에서
뺄지와 잔량을 검증하고, 저장한 변경은 이력과 취소 경로로 연결한다. 모르는 수량은 만들지 않고
질문하거나 미확인으로 남긴다. 명확한 항목만 먼저 저장하는 복합 등록의 부분 반영은 R-01의
미구현 목표이므로 현재 동작으로 소개하지 않는다.

영상에서는 Gemini가 조리 내용을 구조화하고 앱이 단계·타이머·낭독을 제공한다. YouTube Data API는
제목·설명글 등의 조회 경로이며 영상 분석 자체와 구분한다. AI 해석 품질, 서버 계산 검증,
실기기 음성 동작의 증거를 각각 제시한다.

## AI 개발 과정의 설명

모델별 역할은 실제 수행한 기록으로 설명한다. 기획·위험 실험·목업 선택·화면 계약·서버/앱 구현·
검증의 산출물이 어떻게 다음 단계로 연결됐는지 보여준다. 코드 작성과 실기기 완료를 구분한다.
사용하지 않은 도구나 독립 검증을 추가하지 않는다. 개발 시간 절감률은 비교 측정 없이는 주장하지 않는다.

UI/UX 프로세스는 [개발 절차](../runbook/feature-development.md)가 정본이다. 발표 문서에
Compose·가로 태블릿용 별도 개발 지시를 두지 않는다. 실제로 선택한 목업과 구현 전후를 보여준다.

사용한다. 새 버전에서 재측정하지 않았으면 현재 성능 수치로 제시하지 않는다.

## 질문에 답할 기준

대기 중 LLM은 호출하지 않지만 기기 인식 서비스의 외부 처리는 가능하다고 답한다.
기한은 사용자·라벨의 날짜와 종류를 보존하며 안전을 보증하지 않는다.
기록하지 않은 사용은 자동 추정하지 않고 잔량 보정으로 복구한다.
구독·부족 재료 구매 제휴는 가설이며 일반 검색 링크에 제휴 수익이 발생한다고 설명하지 않는다.

최종 발표 전 [검증 기준](../verification/mvp.md)과 실제 결과로 시연 대상을 고른다.
[HTML 브리프](html-brief.md)는 확정된 문구와 실제 자산만 전달받아 제작한다.
