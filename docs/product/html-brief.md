## 역할과 기준 문서

GPT/Codex가 작성한 이야기·문구·연출을 바탕으로 Claude가 실제 HTML 발표자료를 만든다. 이 문서는 제작 지시서이며 앱 구현이나 발표자료가 완성되었다는 증빙이 아니다.

## 제작 목표

사내 동료들이 “이거 우리 집에서도 쓰고 싶다”는 생각을 하게 한다. 현대적인 제품 발표처럼 큰 한글 타이포그래피, 여백, 재료 카드와 태블릿 화면을 중심으로 구성한다. 정보가 단계적으로 드러나는 인터랙션을 사용하고, 발표 시간을 늘리는 장식은 줄인다.

기본안은 차콜 배경·크림색 글자·라임 강조색이다. 재료와 요리에는 따뜻한 색을 쓴다. 작은 표와 코드가 가득한 화면보다 한 문장과 한 장면을 크게 보여준다. 디자인의 세부 표현은 Claude가 결정하되 문구의 의미와 제품 상태를 유지한다.

## 슬라이드별 화면 문구와 진행

### 1. 0:00–0:40 / 문제

큰 제목: **냉장고엔 재료가 있는데, 오늘 뭐 먹지?**

순서대로 드러낼 문구:

1. 재료는 있는데, 메뉴가 안 떠오른다.
2. 영상은 찾았는데, 재료가 있는지 모르겠다.
3. 기록하려니, 요리 중엔 손이 바쁘다.

연출: 냉장고 재료 카드 옆에 요리 영상 모양의 카드가 나타난다. 실제 영상을 확보하기 전에는 가상의 제목·채널·조회 수를 실물처럼 꾸미지 않는다. ‘화면 구성 예시’로 표시한다.

### 2. 0:40–1:15 / 제품

큰 제목: **주방에 두고, 말로 쓰는 「오늘 뭐 먹지?」**

태블릿 주변의 발화: “두부 두 모 넣었어.” / “계란 두 개 썼어.” / “오늘 뭐 먹지?”

하단 문구: **있는 재료 → 메뉴와 영상 / 먹고 싶은 영상 → 필요한 재료**

연출: 태블릿을 중심으로 두 방향을 한 번씩 강조한다. 애니메이션은 설명용이며 음성 감지·LLM 처리처럼 가장하지 않는다.

### 3. 1:15–3:35 / 실제 사용

큰 제목: **말로 기록하고, 영상으로 따라 만들어요.**

상단 진행 표시: 재료 등록 → 사용·정정 → 메뉴·영상 찾기 → 냉장고와 비교 → 부족한 재료 찾기

본 화면은 실제 태블릿 미러링 또는 실제 촬영 영상이 들어갈 자리다. 별도의 HTML 가상 앱으로 실제 제품 동작을 대체하지 않는다. 예비 설명 화면이 필요하면 ‘동작 설명 예시’로 표시한다.

기대 재고: 계란 10개 → 2개 사용 후 8개 → 사용량을 3개로 정정 후 7개.

영상 비교에서 강조할 문구: **있는 재료 / 부족한 재료 / 양을 확인할 재료**

부족한 재료 카드에는 **‘쿠팡에서 찾기’** 버튼을 보여준다. 필요량과 부족량을 표시하고 실제 검색 페이지로 이동하는 장면을 최대 15초로 잡는다. 상품 API를 연결하지 않았다면 가상의 상품·가격·배송 배지를 앱의 실제 결과처럼 만들지 않는다. 발표용 버튼은 의도적으로 눌렀을 때만 외부 페이지를 열고 발표 위치를 보존한다.

분석 결과에는 원본 제목·채널·링크를 남긴다. 실제 분석값을 확보하기 전에는 재료 비교 예시를 실측값처럼 표시하지 않는다. 저장한 분석 결과를 보여줄 경우 ‘사전 분석 결과 · 현재 재고와 비교’라고 표시한다. 첫 분석의 실제 녹화본은 예비 자료로 둔다.

### 4. 3:35–4:20 / 설계 이유

큰 제목: **말과 영상은 AI가 이해하고, 재고는 코드로 확인합니다.**

주 흐름: Porcupine 호출 감지 → Android 음성 인식 → LLM 의도 해석 → 검증·계산·저장 → 화면·음성 응답

아래 별도 흐름: YouTube 검색 / 영상 링크 → 영상 레시피 분석 → 현재 재고 비교

짧은 설명: “대기는 기기에서” / “영상 속 분량이 없으면 미확인” / “검색된 영상과 분석한 영상을 구분”

실제로 채택한 제품용 모델명은 작은 보조 라벨로 넣는다. 미정일 때는 ‘명령용 LLM’, ‘영상 분석 모델’로 표시한다.

### 5. 4:20–5:35 / AI로 만든 과정

큰 제목: **기획부터 검증까지, AI와 어떻게 만들었나.**

단계별 문구:

- GPT: 문제·범위 정리, 기술 검토와 작은 실험
- UI/UX: 음성 상태, 주방에서 읽히는 글자, 결과와 정정 흐름
- Claude: 문서와 실행 조건을 기준으로 Android·서버 구현
- 개발자: 실제 태블릿 검증, 실패 수정, 완료 판정
- GPT → Claude: 발표 이야기·문구 → HTML 제작

하단 문구: **제품 요구 → 설계 → 코드 → 검증 결과를 문서로 연결**

연출: 단계마다 실제 문서·실험 기록·화면 전후 중 하나를 보여준다. 사용한 도구·작업은 개발 후 사실에 맞춰 갱신한다. 모델별 우월성을 주장하는 비교 그래프는 넣지 않는다.

### 6. 5:35–6:20 / 증거

큰 제목: **동작은 실제 주방 태블릿에서 확인합니다.**

개발 후 사용할 내용: 호출 결과 `[성공/시도·조건]`, 재고 정정 `[기대값/실제값]`, 영상 추출 `[확인 영상 수·누락 내용]` 중 2~3개.

옆에 실제 문제 하나와 수정 결과를 보여준다. 측정 전에는 ‘검증 예정’으로 두며 임의의 수치·완료 배지·차트를 생성하지 않는다. HTML 제작 편의상 채운 숫자도 발표본에 남기지 않는다.

### 7. 6:20–7:00 / 다음 단계

큰 제목: **영상에서 먹고 싶어진 요리를, 우리 집 저녁으로.**

짧은 문구: “집에서 자주 요리하는 가구부터” / “일주일간 실제 요리와 반복 사용 확인” / “개인화 구독·부족한 재료의 구매 제휴 검증”

마지막 문장: **장본 것을 말로 넣고, 쓴 것을 말로 빼고, 남은 것으로 오늘 저녁을 정합니다.**

사업 모델은 가설이다. 영상 분석에 대한 지불 의사·처리 원가와 구매 연결의 이용률을 확인할 계획으로 설명한다. 일반 검색 연결에 제휴 수익이 발생한다고 표현하지 않는다.

## HTML 동작 요구

- 16:9 발표 화면. 실제 발표 해상도에서 잘림 없이 확인한다.
- 좌우 방향키·Space·화면 버튼으로 진행. 다음 클릭은 문구 공개 또는 다음 슬라이드로 일관되게 동작한다.
- 이전 이동·처음으로·슬라이드 직접 이동을 지원한다. 새로고침 후 위치 유지 여부도 명시한다.
- 발표자 노트는 청중 화면에서 숨기며, 별도 창 또는 별도 문서로 볼 수 있게 한다.
- 전체 화면 버튼, 현재 슬라이드와 전체 진행 표시를 제공한다. 입력창에 포커스가 있을 때 진행 키가 입력을 가로채지 않는다.
- 애니메이션은 발표자의 클릭에 맞춘다. 자동 슬라이드 넘김·자동 영상 재생은 사용하지 않는다.
- 실제 앱의 라이브 시연과 발표용 애니메이션을 시각적으로 구분한다.
- 폰트·이미지·예비 시연 영상은 가능한 한 로컬 자산으로 준비한다. 실제 API 키를 HTML에 넣지 않는다.
- PDF 인쇄용 정적 레이아웃과 영상 실패 시 설명 화면을 제공한다. 모든 공개 단계의 핵심 문구가 인쇄본에 나타나야 한다.
- 구현하지 않은 기능, 성능, 사용자 수, 비용 절감 수치를 추가하지 않는다.

## Claude에 전달할 요청문

> 이 브리프와 연결된 발표 대본을 읽고 7분용 HTML 발표자료를 제작해줘. 제품 소개와 실제 시연을 먼저, 기술 설계와 AI 개발 과정은 뒤에 배치해줘. 큰 한글 타이포그래피와 재료·영상·태블릿 중심의 시각 구성, 클릭에 맞춘 단계적 공개로 표현해줘. 발표 대본을 전부 화면에 옮기지 말고 화면 문구와 발표자 노트를 구분해줘. 실제 앱 화면·영상·검증 결과가 없는 자리는 필요한 자산을 명시하고 미확인 상태를 유지해줘. HTML로 실제 제품이 동작하는 척하지 말고, 키보드 진행·로컬 자산·정적 예비 화면까지 실제 발표 환경에서 확인해줘.
