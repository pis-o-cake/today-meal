# HTML 발표자료 제작 브리프

9/30 18:00 제품 제출 이후 제작한다. [발표 계획](presentation-plan.md)의 7분 흐름을 HTML로
표현하며 앱 개발의 기준 문서로 사용하지 않는다. 실제 구현 여부는 작업표와 검증 증거로 확인한다.

## 제작 기준

- 내용·진행 순서는 발표 계획을 따른다. 문장 하나와 실제 폰 화면을 중심으로 구성한다.
- 앱 화면은 [현재 목업](../../mockup/README.md)과 검증된 실기기 화면을 구분한다.
- 목업·가상 데이터·설명 애니메이션은 그 사실을 표시한다. API·음성 처리가 되는 것처럼 꾸미지 않는다.
- 추가 영상·쿠팡 기능은 검증됐을 때만 실제 사용 장면에 넣는다.
- 현행 기술은 Flutter·내장 인식 반복 청취·서버 Gemini·PostgreSQL이다. Porcupine 구성도를 쓰지 않는다.
- 핸드폰 전경 호출과 태블릿 백그라운드 상시 대기를 구분한다.

## 슬라이드와 자산

| 순서 | 화면 문구 | 필요한 자산 |
|---|---|---|
| 1 | 냉장고엔 재료가 있는데, 오늘 뭐 먹지? | 사용자 상황 설명 |
| 2 | 말로 기록하고, 남은 재료로 저녁을 정해요 | 실제 폰 화면·호출 안내 |
| 3 | 넣고 → 쓰고 → 고치고 → 메뉴를 골라요 | 실기기 미러링 또는 녹화, 잔량 변화 |
| 4 | 말은 AI가 해석하고, 재고는 서버가 검증해요 | 현행 구조도 |
| 5 | 목업과 동작 기준을 연결해 구현했어요 | F-ID·UI-ID·V-ID, 문서·화면 전후 |
| 6 | 어디까지 확인했나요? | 실제 조건·결과·남은 문제 |
| 7 | 다음 저녁에도 쓸 수 있도록 | 반복 사용 검증 계획·후속 범위 |

자산이 없으면 필요한 자산명과 미확인 상태를 표시한다. 임의 성공률·사용자 수·가격·절약액을
채우지 않는다. 실제 시연 날짜와 데이터, 앱·서버 버전을 자료에 맞춘다.

## HTML 동작 요구

16:9에서 큰 한글 타이포와 여백을 사용한다. 키보드 방향키·Space·버튼으로 문구 공개와
슬라이드 이동을 일관되게 제공하고 입력창 포커스에서는 진행 키를 가로채지 않는다.
이전·처음·직접 이동·전체 화면·진행 표시를 제공한다. 새로고침 위치 보존 여부를 정해 표시한다.

발표자 노트는 청중 화면에서 숨긴다. 자동 넘김·자동 영상 재생은 하지 않는다.
외부 링크는 명시적 클릭으로만 열고 복귀 시 발표 위치를 유지한다.
폰트·이미지·예비 영상은 로컬 자산을 우선하며 API 키를 HTML에 넣지 않는다.
PDF 인쇄 시 모든 핵심 문구가 표시되고 영상 실패용 정적 화면이 있어야 한다.

실제 발표 브라우저에서 진행·뒤로·영상 실패·오프라인 자산·PDF 출력을 확인한다.
미실행 항목을 완료로 기록하지 않는다.
