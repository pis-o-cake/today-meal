# ‘오늘 뭐 먹지?’ 발표 스토리보드 v2

발표 7분 이내(시연 영상 포함) + 별도 질의응답 3분. 9장, 목표 **5분 50초**(리허설 전 추정).
웹 슬라이드는 `slides-v2/index.html`, 발표자 대본·노트·시간은 `slides-v2/presenter.html`(청중 화면에서 `P`).
기존판(`storyboard.md`, `slides/`)은 그대로 두고 비교용으로 남긴다.

- 핵심 주장: **재료를 기록하는 데서 끝내지 않고, 메뉴 선택·조리·남은 재고까지 연결한다.**
- 남길 것 세 가지: 집중한 사용자 문제, AI를 쓰며 개발자가 한 판단과 검증, 확인한 결과와 앞으로 검증할 것.
- 음식물 낭비 감소·시간 절약·지속 사용 효과는 검증 전이라 성과로 말하지 않는다.
- 청중 화면은 주장과 증거만 두고, 설명은 발표자 대본으로 뺀다.
- 글꼴: 표지 제품명·장 제목·마지막 중심 문구는 배민 주아체(합성 굵기·외곽선·그림자 없음), 본문·표·수치·조작 안내는 Pretendard.

## 기존판과 다른 논리

| 기존판 | v2 |
|---|---|
| 기능 소개 3장(기한별 홈·음성 기록·메뉴) 뒤 시연 | 흐름 지도 1장으로 줄이고 “영상에서 볼 것”을 먼저 말한다 |
| 시연 직후 AI 도구 소개 | 시연 직후 **확인한 결과 세 가지**를 보이고, 한계는 한 문장으로 둔다 |
| 기술 선택(Gemini·호출어) 중심 8장 | **AI는 해석, 서버는 검증** 한 가지 주장만 명령 예시 하나로 보인다. Gemini 이유는 6장 대본에 한 문장 |
| 7장 도구 표 | 네 단계(번호·단계명·도구·설명)를 장 진입 때 한 번에 보인다. 실기기 판단 사례는 대본으로만 |
| 마무리에서 다음 목표 한 줄 | 8장을 **성패를 가를 질문 세 가지**로 따로 두고, 9장은 캐릭터·제품명·중심 문구만 남긴다 |

## 장별 근거와 주의

- **1장:** 도구·기술 이름을 꺼내지 않는다.
- **2장:** 1~2인 가구는 초기 대상 가정이다. 조사 결과나 통계처럼 말하지 않는다.
- **3장:** 화면은 `rec-egg10`·`home-urgent`·`cook-timer`(10/1 실기기 녹화)와 `cook-done`(90초 v3 영상 73.5초 프레임).
  추천 조리 완료는 조리한 인분 기준으로 맞출 수 있는 재료만 뺀다. 유튜브 레시피 조리는 자동 차감이 없다.
- **4장:** `assets/video/demo.mp4` = `demo/final/voiceover/today-meal-90s-v4-ai-voice-leda.mp4`(87초).
  사용자 목소리만 AI 후시 녹음, 앱 응답·신호음은 실제 녹화음. 후시 녹음·대기 단축·단계 생략 표시는 유지한다.
  영상 중에는 말하지 않는다. 정정·취소·복합 등록·4인분 변경은 영상에 없다.
- **5장:** 근거는 `demo/final/EDIT-NOTES.md`. 화면에는 확인한 결과 세 가지와 한계 한 문장
  (“Android 실기기 1대의 편집 시연이며, 반복 사용 안정성과 생활 효과는 추가 검증이 필요합니다.”)만 둔다.
  정정·취소·복합 등록 등 미시연 항목과 편집 기록의 한계(05 끝 냉장고 화면 계란 10개라 제외, “undo” 말풍선, “있어요” 표시 오류)는 발표자 노트에 둔다.
  영상이 전체 과정의 재고 정합성을 입증한다고 말하지 않는다.
- **6장:** “재고 변경을 어떻게 통제하는가” 하나에 집중한다. 구현 목록(되묻기·전부 아니면 반영 안 함·이력·취소·정정)과
  부분 반영 미구현 목표(검증 기록 R-01)는 발표자 노트에 둔다. Gemini 선택 이유는 대본 한 문장
  (공식 문서 ai.google.dev/gemini-api/docs/video-understanding, 2026-09-23 갱신 기준 YouTube URL 입력은 **프리뷰** 기능 — 노트에 표기).
- **7장:** 제목 “기획부터 구현까지, 단계마다 AI 활용”. 네 단계를 왼쪽에서 오른쪽으로 같은 비중으로 두고 번호·단계명·도구·설명을 여백과 정렬로 구분한다.
  카드·로고·아이콘·사례 상자는 없다. 단계 공개가 없어 장 진입 때 전부 보이고, 다음 Space 가 바로 8장으로 간다(모션은 장 전환 페이드뿐).
  실기기 판단 사례(앞말 잘림 → 신호음 → 촬영에서 재확인)는 대본으로만 말한다. 근거: `app/lib/core/voice/listening_cue.dart`(9/30 22:49, 커밋 6dacd9a)와
  9/30 23:13 이후 촬영본 받아쓰기. 정량 개선이나 전체 해결로 말하지 않는다. Claude Design 창 전환은 없다. engsys는 기존 개발 지원 도구다.
- **8장:** 대본은 “다음으로 확인할 것은 실제 생활에서도 이 흐름이 유지되는가입니다.”로 시작한다. 확인 방법이 제안이라는 표시는 한 번만 둔다.
  다음 검증 이야기는 이 장에서 끝낸다. 호출은 앱 전경에서만, 실기기 확인은 Android뿐이다.
- **9장:** 캐릭터, 작은 제품명, 주아체 중심 문구(냉장고 속 재료가 / 오늘의 한 끼로.)만 둔다. 기능 설명·검증 계획·감사 페이지는 없다.

## 근거가 부족해 넣지 않은 주장

- 음식물 낭비 감소, 시간 절약, 지속 사용 효과
- 1~2인 가구의 불편을 조사로 확인했다는 표현이나 통계
- 음성 인식률·호출 정확도, 신호음 수정의 정량 개선
- 처음부터 끝까지 이어진 재고 정합성(장면별 촬영 편집본)
- GPT/Astra의 구체 산출물(기록이 없어 “선택지 비교, 구현 방향 정리”까지만)
- 자동 테스트 수치(질문 시에만 날짜·커밋과 함께)
