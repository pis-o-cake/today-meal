# 시연 촬영 대본 — 전체 기능 버전과 발표용 90초

실제 앱 시연 영상을 제작한다. 전체 기능 버전 6~7분과 발표용 90초 두 가지가 필요하다.
긴 버전을 아래 챕터별로 따로 촬영한 후 합치고, 같은 원본에서 짧은 버전을 편집한다.

Claude는 기기 연결·녹화 시작/종료·파일 저장·녹화 확인을 담당한다.
사용자는 안내에 따라 실제 발화와 화면 조작을 한다.
앱 기능을 수정하거나 DB를 초기화하는 작업은 촬영과 분리한다.

## 촬영 환경부터 확인

1. adb 연결 기기와 설치 앱 버전, 연결된 서버를 확인한다.
2. 서버가 실제 Gemini를 사용하는지 확인한다.
3. 화면과 사용자 마이크 음성, 앱 TTS가 함께 담기는 방법을 먼저 시험한다.
   `adb shell screenrecord`만으로 마이크까지 녹음된다고 가정하지 않는다.
   기기 Android 버전과 녹화 도구의 오디오 지원을 확인하고,
   필요하면 scrcpy 또는 별도 음성 녹음을 조합한다.
4. 10초 시험 녹화에서 사용자 목소리와 앱 응답이 실제 파일에 들어갔는지 확인한다.
   스피커로 나오는 앱 응답을 마이크로 녹음하면 이중 녹음·울림을 확인한다.
5. 알림 방해 금지, 세로 화면, 글자 크기, 음량, 화면 꺼짐 시간을 맞춘다.
6. 촬영은 별도 시연 계정으로 한다. 기존 사용자 데이터를 지우지 않는다.
7. 유통기한은 촬영일 기준 삼겹살 D+1, 두부 D+2, 계란 D+3으로 정한다.
   촬영 시작 전에 실제 발화할 월·일을 알려준다.
8. 메뉴 상세의 잘못된 ‘있어요’ 표시 등 알려진 결함을 확인한다.
   잘못된 표시를 숨기는 편집으로 해결하지 않는다.
9. 기능별 사전 시험 결과로 촬영 가능 여부를 판정한다.
   확인 질문·후속 답변·부분 반영·완료 차감 등을 된다고 가정하지 않는다.

## 챕터 진행 방식

각 챕터마다 다음 순서로 진행한다.

- 시작 화면과 필요한 재고를 확인한다.
- 사용자가 할 발화·터치 순서를 짧게 알려준다.
- 녹화를 시작하고 “시작해도 됩니다”라고 알려준다.
- 사용자가 끝났다고 하면 2초 여유를 두고 녹화를 종료한다.
- 영상·음성·결과 수량을 확인하고 파일 경로를 알려준다.
- 실패한 테이크는 원인을 확인한 뒤 별도 번호로 다시 찍는다.
- 다음 챕터를 임의로 시작하지 않는다.

원본 파일명:

```text
01-시작-take01.mp4
02-등록-take01.mp4
03-냉장고-take01.mp4
04-사용정정-take01.mp4
05-추천조리-take01.mp4
06-영상레시피-take01.mp4
07-설정-take01.mp4
08-마무리-take01.mp4
```

원본은 보존하고 편집본은 별도로 만든다.
아래 시간은 편집 후 목표이며 실제 응답을 재촉하지 않는다.

## CHAPTER 01. 오늘 뭐 먹지? — 약 25초

**목적:** 냉장고에 있는 재료로 오늘의 메뉴를 정하는 앱이라는 점을 소개한다.

**시작:** 로그아웃 또는 첫 진입 상태. 계정 생성 장면이 필요하면 촬영용 정보만 사용한다.
비밀번호·토큰·개인 이메일을 노출하지 않는다.

**조작**

1. 앱 실행과 스플래시.
2. 촬영용 계정 로그인.
3. 권한 화면이 나오면 마이크 허용.
4. 홈 도착 후 3초 정지.

**자막**

> 오늘 뭘 먹을지 고민될 때
>
> 냉장고에 있는 재료부터 살펴봅니다.

**주의:** 가입·로그인·게스트 경로를 모두 처음부터 끝까지 반복하지 않는다.
별도 경로를 추가 촬영하면 편집에서 구분한다. 홈에서 음성 호출이 가능한 상태로 끝낸다.

## CHAPTER 02. 말로 재료 기록 — 약 65초

**목적:** 재료·수량·유통기한을 자연어로 기록하고, 말하지 않은 날짜는 임의로 만들지 않는 모습을 보여준다.

**시작:** 촬영용 냉장고가 비어 있는지 확인. 기본 인분은 2인분.
날짜는 촬영일 기준으로 미리 확정한다.

**발화:** 매번 “헤이 키친”으로 부르고 준비 응답을 기다린 뒤 말한다.

1. “계란 열 개 넣었어. 유통기한은 [D+3 월일]까지야.”
2. “삼겹살 300그램 넣었어. 유통기한은 [D+1 월일]까지야.”
3. “두부 두 모 넣었어. 유통기한은 [D+2 월일]까지야.”
4. “대파 한 단 넣었어.”

**화면:** 첫 등록은 호출 → 준비 응답 → 발화 → 전사 → 반영 결과를 끊지 않고 담는다.
각 반영 결과에서 수량과 기한을 읽을 수 있도록 2~3초 정지한다.
대파는 실제 질문 또는 저장 결과에 맞춰 진행한다.

**예상 최종 재고:** 계란 10개 / 삼겹살 300g / 두부 2모 / 대파 1단.

**자막**

> 재료와 유통기한을 말로 기록
>
> 날짜를 모르면 미확인으로 관리

**선택 추가 테이크:** 복합 등록을 사전 시험으로 확인했다면 별도 촬영한다.
예: “양파 두 개랑 감자 세 개 넣었어.”
명확한 복합 등록과 ‘일부만 저장하고 나머지를 질문하는 기능’은 구분한다.
확인 질문과 후속 답변은 실제로 연결되는 경우에만 촬영한다.
추가 재료가 이후 추천에 영향을 준다는 점을 기록한다.

개봉·보관 이동도 사전 시험에 통과하고 실제 발화 계약이 확인된 경우 추가 테이크로 촬영한다.
65초 안에 억지로 모두 넣지 않는다.

## CHAPTER 03. 먼저 쓸 재료 확인 — 약 45초

**목적:** 이 앱의 핵심인 홈의 기한별 슬라이드와 냉장고 상태를 보여준다.

**시작:** 네 재료가 등록된 홈.

**조작**

1. 홈에서 기한별 슬라이드를 천천히 넘긴다.
2. 각 상태의 재료·문구·캐릭터 변화가 보이도록 2~3초씩 머문다.
3. 먼저 써야 할 삼겹살 상태를 보여준다.
4. 냉장고 탭으로 이동해 네 타일을 보여준다.
5. 검색창에 “두부” 입력 → 검색 결과 → 검색 해제.
6. 보관 필터를 한 번 선택하고 전체로 복귀.
   실제 보관 위치가 입력돼 있는 경우에만 필터 결과를 설명한다.

**자막**

> 먼저 써야 할 재료를 한눈에
>
> 기한이 임박한 삼겹살부터 오늘의 메뉴로

**선택 추가 테이크:** 두부 상세 → 수동 수량 수정 → 기록에서 되돌리기.
두부 버리기 → 되돌리기로 복원.
사전 시험에서 복원까지 확인한 경우만 담고, 챕터 종료 시 두부가 2모로 돌아왔는지 확인한다.

**주의:** 홈의 기한별 전환은 발표용 90초에도 반드시 포함한다.
목록 순서나 자동 정렬은 실제 화면에서 확인한 만큼만 설명한다.

## CHAPTER 04. 사용·정정·취소·잔량 보정 — 약 60초

**목적:** 잘못 말하거나 기록을 놓쳐도 실제 잔량으로 바로잡는 과정을 보여준다.

**시작:** 계란 10개. 직전 사용 기록에 다른 행동이 끼지 않도록 한다.

**발화와 확인:** 매번 “헤이 키친”으로 부르고 준비 응답 뒤 말한다.

1. “계란 두 개 썼어.” → 10 → 8개.
2. “두 개가 아니라 세 개 썼어.” → 8 → 7개.
   추가 3개 차감으로 5개가 되면 실패한 테이크다.
3. “방금 거 취소.” → 정정 취소 후 7 → 8개.
4. “계란 네 개 남았어.” → 현재 잔량 4개로 보정.
5. 기록 탭에서 사용·정정·취소·보정과 변경 전후를 보여준다.

**자막**

> 사용량을 반영하고
>
> 잘못 말한 양은 정정하고
>
> 실제 남은 양으로 맞춥니다.

**주의:** 각 단계의 수량이 맞는지 확인하고 다음으로 진행한다.
결과가 다르면 정상처럼 편집하지 않는다. 이후 챕터는 계란 4개 기준으로 진행한다.

## CHAPTER 05. 냉장고 재료가 오늘의 메뉴로 — 약 80초

**목적:** 먼저 쓸 재료 확인 → 메뉴 결정 → 조리의 연결을 보여준다.

**시작:** 삼겹살 300g이 기한 임박 상태. 홈 또는 냉장고에서 해당 상태를 보여준다.

**발화**

> “헤이 키친” → 준비 응답 → “삼겹살로 뭐 해먹을까?”

**조작**

1. 실제 추천 화면으로 이동하는 과정을 담는다.
2. 추천 목록과 실제 표시된 추천 이유를 보여준다.
3. 카드 본문을 눌러 메뉴 상세로 들어간다.
4. 2인분 재료 수량을 보여준다.
5. 인분 + 두 번 → 4인분.
6. 같은 재료 행에서 수량이 바뀐 결과를 보여준다.

**자막**

> 먼저 쓸 재료로 메뉴 추천
>
> 먹을 인원에 맞춰 필요한 양 조절

**주의:** 추천 메뉴명과 수량은 실제 결과를 사용한다.
보유량 대비 부족 표시가 실제로 지원될 때만 설명한다.

**조리 테이크**

7. 실제 보유 재고로 진행 가능한 인분을 선택한다.
   4인분이 부족하면 2인분으로 되돌리는 장면을 포함한다.
8. 조리 시작.
9. 단계 안내·낭독을 담는다.
10. 사전 시험에 통과했다면 “다음”, “다시 읽어 줘” 같은 실제 지원 명령과 타이머 조작을 보여준다.
11. 중간 단계는 편집으로 압축하고 “조리 단계 이동 일부 생략”을 표시한다.
12. 완료 → 서버가 반영한 차감 결과.
13. 냉장고 또는 기록에서 실제 수량 변화를 확인한다.
14. 되돌리기 → 원래 재고로 복원됐는지 확인한다.

**추가 자막**

> 조리한 인분 기준으로 재고 반영
>
> 잘못 완료했다면 되돌리기

완료 차감과 되돌리기는 촬영 전 왕복 시험에 통과한 경우만 촬영한다.
서버가 확인 질문을 반환하거나 차감하지 않았다면 ‘차감 완료’라고 설명하지 않는다.
실제 요리 장면은 없으므로 음식이 완성된 것처럼 연출하지 않는다.

## CHAPTER 06. 유튜브 레시피도 조리 안내로 — 약 45초

**목적:** 레시피 링크를 재료와 조리 단계로 바꾸는 기능을 보여준다.

**시작:** 접근 가능한 공개 요리 영상 URL을 미리 준비한다.
제목·영상 내용·분량이 결과와 맞는지 사전 확인한다.

**조작**

1. 조리 탭에서 유튜브 링크 붙여넣기.
2. 분석 요청.
3. 분석 중 상태를 담는다.
4. 결과의 영상 제목·재료·조리 단계를 보여준다.
5. 영상 분석 결과로 조리 시작.
6. 단계 화면과 낭독을 잠깐 보여준다.

**자막**

> 유튜브 링크를 재료와 조리 단계로
>
> 분석한 레시피를 따라 조리 시작

**주의:** 실제 분석 대기를 줄이면 “분석 대기 구간 단축” 표시.
저장된 분석을 불러온 경우 새 분석처럼 설명하지 않는다.
재고 대조는 실제 표시된 범위에서만 설명한다.
영상에서 시작한 조리는 완료해도 자동 차감하지 않는다는 제한을 긴 버전 자막에 짧게 남긴다.
영상 검색 기능으로 소개하지 않는다.

## CHAPTER 07. 내 사용 방식에 맞추기 — 약 30초

**목적:** 설정이 실제 앱 동작에 반영되는 모습을 보여준다.

**조작**

1. 마이페이지에서 테마 변경 → 홈 화면 변화 확인.
2. 기본 인분 변경 → 새 추천 요청의 인분 반영 확인.
   기존에 만든 추천 상세까지 자동 변경된다고 가정하지 않는다.
3. 기한 강조 설정 변경 → 냉장고 표시 변화 확인.

**선택 추가 테이크:** 음성 응답 끄기 → 같은 조회에서 TTS가 나오지 않는지 확인 → 다시 켜기.

**자막**

> 화면과 음성, 기본 인분을 내 방식으로

**주의:** 설정 화면의 스위치 변화만으로 동작 반영을 주장하지 않는다.
발표용 짧은 버전에는 이 챕터를 넣지 않는다.

## CHAPTER 08. 복구와 마무리 — 약 20초

**목적:** 실수했을 때의 처리와 서비스 목적을 정리한다.

**선택 복구 테이크:** 현재 보유량보다 큰 사용량을 말한다.
예: 계란이 4개일 때 “계란 스무 개 썼어.”
저장하지 않고 확인하는 실제 결과와 잔량 유지를 보여준다.
후속 답변 기능이 미연결이면 연결된 것처럼 이어 붙이지 않는다.

**마무리:** 홈으로 돌아와 기한별 슬라이드를 한 번 넘기고 정지한다.

**마지막 자막**

> 먼저 써야 할 재료가 오늘의 한 끼로.
>
> 오늘 뭐 먹지?

챕터 01~08 편집 목표 합계는 약 6분 10초다.
추가 기능 테이크와 전환을 포함해 6~7분 내로 정리한다.
모든 기능을 넣기 위해 읽을 수 없을 정도로 빠르게 편집하지 않는다.

## 발표용 90초 편집본

긴 버전 원본에서 다음 순서로 추출한다.

| 구간 | 장면 | 원칙 |
|---|---|---|
| 00~08초 | 홈 기한별 슬라이드 | “오늘 뭐 먹지? 먼저 써야 할 재료부터.” |
| 08~28초 | 음성 등록 1회 | 첫 호출·준비 응답·발화·결과는 실제 속도 유지 |
| 28~38초 | 사용 → 정정과 실제 잔량 변화 | 읽을 시간이 부족하면 정정은 빼고 홈·추천 장면에 배분 |
| 38~65초 | 기한 임박 삼겹살 → 메뉴 요청 → 추천 → 인분 변경 | 대기 단축 표시 |
| 65~78초 | 검증된 조리 단계와 완료 차감 | 차감이 촬영에서 확인되지 않았다면 단계 안내로 끝냄 |
| 78~85초 | 유튜브 링크와 실제 분석 결과 | 이해되지 않을 정도로 짧으면 별도 기능 자막으로 단순화 |
| 85~90초 | 홈과 중심 문장 | “냉장고를 비우는 한 끼로 연결합니다.” |

발표용에서도 홈의 기한별 슬라이드와 먼저 쓸 재료→추천 연결을 우선한다.
90초에 넘치면 부가 기능 장면부터 줄인다.
사용자 발화·앱 응답 위에 설명 내레이션을 겹치지 않는다.
긴 버전과 짧은 버전은 촬영일·앱 버전·데이터가 같은 원본을 사용한다.
